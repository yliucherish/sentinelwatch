# 窗口频次判据评测：CIC-IDS2017 Tuesday-WorkingHours（2017-07-04，纯 HTTP 良性语料）

- PCAP：`data\Tuesday-WorkingHours.pcap`（10.3 GB）
- 规则：`http-login-brute-force` — 60s 滑动窗口 / 阈值 30 次 / 命中后静默 300s
- 扫描：全天 48345 条 HTTP 请求，其中命中登录端点 57 条，涉及 10 个源 IP
- 耗时 130.8s（单线程，含解析）

> ⚠️ **粒度声明**：本报告的 TP/FP 是**告警（窗口）级**，不是逐请求级。它与 `bench/run_benchmark.py` 的混淆矩阵**不能相加、不能互相替换**。一次爆破的 N 条请求合起来才是一次攻击，逐条摊进矩阵会让两个指标同时失去意义。

## 阈值标定依据（只看突发分布，不用攻击标签）

- 任一源 IP 在任意 60s 窗口内的**峰值**登录请求数：**4**（分组 `192.168.10.5`）
- 本数据集标注口径：`all-benign`（全良性，无攻击窗）

## 告警级结果（与主矩阵分开）

| 指标 | 值 | 说明 |
|---|---:|---|
| 产生告警 | 0 | 窗口级，静默期内不重复报 |
| 告警 TP | 0 | 告警区间与标注攻击窗相交、且源 IP 为该窗攻击源 |
| 告警 FP | 0 | 未与任何标注攻击窗相交（含全良性数据集上的全部告警）|
| 告警精确率 | — | 无告警，精确率无定义 |
| 落在 Brute Force 窗的告警 | 0 | 本次补强直接针对的攻击类型 |
| Brute Force 窗覆盖 | 0/0 | 每个标注窗至少有一条 TP 告警即算覆盖 |
| Brute Force 窗内登录请求 | 0 | 改进前签名规则对它们的命中是 **0**，见 BENCHMARK.md §2.6 |
