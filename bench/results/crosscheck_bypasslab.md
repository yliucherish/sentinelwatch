# 跨项目交叉评测：bypasslab 语料 × sentinelwatch 规则

- 语料：`corpus_full.json`（228 条样本；由 bypasslab 的 `go run ./cmd/export` 生成）
- 参与评测的签名规则：27 条；另有 3 条窗口/阈值规则未参与（见下方口径）

> ⚠️ **两条口径，缺一条数字就不可信**：
> 1. 只测**签名规则**。`threshold > 1` 的窗口规则要多次事件才成立，单条样本无法评测——它们不参与本报告，**不等于漏检**。
> 2. **能力边界不计入分母**：没有判据的类别记 `unsupported` 并排除在检出率之外。把「没有这个能力」算成 0% 命中，是拿分母惩罚自己。v2.1 起只剩 `scanner` 一类在外面，而它是**做得到但不做**（判据 8/8 命中、全量良性精度 0/80），不是做不到。

## 四轮修复的账（同一份语料，只差归一化与判据）

| 版本 | 检出/分母 | 检出率 | SQLi | XSS | 路径遍历 | 反序列化 | RCE | SSRF | 改了什么 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| v1.8 | 58/117 | 49.6% | 16/50 | 20/32 | 13/20 | 9/15 | — | — | 首测；定位到 `+` 缺口 |
| v1.9 | 65/117 | 55.6% | 23/50 | 20/32 | 13/20 | 9/15 | — | — | 只修 form `+` 解码 |
| v2.0 | 107/117 | 91.5% | 47/50 | 26/32 | 20/20 | 14/15 | — | — | 判据从「枚举写法」改成「描述形状」 |
| v2.1 | 150/184 | 81.5% | 47/50 | 26/32 | 20/20 | 14/15 | 26/49 | 17/18 | 补命令注入与内网回连判据，`rce` / `ssrf` 首次进分母 |

**前两组的 117 是同一批样本，可以逐列比。v2.1 不行**：它把 `rce` 49 条与 `ssrf` 18 条从「范围外」挪进了分母，分母 117 → 184，总分因此从 91.5% 掉到 81.5%——**这不是退步，是量了更多东西**。
可比的是那四列的分母从头到尾没变，四轮下来一条没掉：`sqli` 47/50、`xss` 26/32、路径遍历 20/20、反序列化 14/15。**加规则时最该验的就是这一句**：新判据有没有把旧判据挤掉。

**这一列里没有一条是靠调松阈值换来的**——误报数一直没涨（见下面的误报样例，它从 v1.8 到 v2.1 都是同一条）。

## 缺口归因：哪些已关闭、哪些是代价

### 1. 已关闭：编码层缺口（v1.9 / v2.0）

v1.8 首测发现 `+` 没有按 form 编码还原：`id=1+UNION+SELECT+...` 归一化后仍是 `1+union+select`，规则里的 `union select` 匹配不到。**form 编码因此成了一种不需要懂漏洞就能用的绕过语法。**

v1.9 修掉 `+`（`_judgement_text()`，只动 query 与 form body，且必须在 `unquote()` 之前）。v2.0 又在同一条解码链上补了两层：IIS 的 `%uXXXX`（`unquote()` 不认这个方言）与 HTML **数字**实体（`&#111;nerror`）。三层都只在判据视图上做，`raw` 一个字没动——判据可以归一化，证据不能。

### 2. 已关闭：判据形态缺口（v2.0）

剩下的漏检绝大多数不是「没解出来」，而是**判据只会枚举写法**：

| 缺口 | v1.8 的判据 | v2.0 的判据 |
|---|---|---|
| `union/**/select`、`union\nselect`、`un/**/ion` | 4 个子串 | 一条正则 + `sql_view`（注释归一成空白） |
| `1234 OR 1=1`、`and 526=527` | 只认 `' or ` + `=1--` | 布尔条件语法（and/or + 比较式） |
| `; DROP TABLE` | 无 | 分号 + DDL 动词 |
| `extractvalue(` / `updatexml(` | 无 | 报错注入函数族 |
| `ontoggle=` / `eval(atob(` | 6 个 `on*=alert` 字面量 | 标签 + 事件属性 + 执行函数（结构） |
| `<x:script>` | 无 | 任意命名空间前缀 |
| `.../...`、`0x2e0x2f` | 无 | 三种「点 + 分隔符」编码变体 |
| `%c0%af` 超长 UTF-8 | 无 | 在 `raw` 上匹配「不可能由正常客户端产生」的编码 |
| `${${lower:j}ndi:` | `${jndi:` 字面量 | `ndi:` + 短填充 + `://` |
| `"@type":"java.net.Inet4Address"` | 三个黑名单类名 | 全限定类名的形状（≥3 段点分） |
| `rO0AB...` | 无 | Java 序列化魔数（带 base64 边界） |

每一行的改法都一样：**把「某个样本长什么样」换成「这类攻击在语法上必须满足什么」**，所以在没见过的变体上仍然成立。证据是 `holdout` 冻结集：v1.8 只有 7/19，v2.0 的判据改写把它抬到 11/19，v2.1 补上命令注入语法又到 15/19——**三轮里没有一次针对 holdout 调过什么**，它从头到尾只被当尺子用。

### 3. 范围外：不是「做不到」，是「做得到但不做」

只剩 `scanner` 8 条（UA 指纹：sqlmap / Nikto / nmap 等）不进分母。它跟 v2.0 之前的 `rce` / `ssrf` **不是同一种东西**：

| 类别 | v2.0 的状态 | v2.1 的状态 |
|---|---|---|
| `rce` 49 条 | 没有判据，范围外 | 有判据，**进分母**（见上表） |
| `ssrf` 18 条 | 没有判据，范围外 | 有判据，**进分母**（见上表） |
| `scanner` 8 条 | 没有判据，范围外 | **判据写过、测过，故意不默认开** |

扫描器那道判据在 bypasslab 语料上是 **8/8**，看着完美；拉到 CIC 三份全量良性流量上却报了 **80 条**，而且 80 条全部来自同一台内网主机（`192.168.10.8`）的 **Nmap NSE**，扫的是 `/.git/HEAD`、`/HNAP1`、`/robots.txt`。从行为上讲那**就是扫描**，判成「误报」是标注口径的结果；但一条在良性流量上精度 0/80 的规则不该默认开着——80 条告警只说明「有台机器在扫」，要按源 IP 聚合 + 例外名单才有意义。所以这一类留在分母外，**理由从「没这个能力」改成了「量完之后决定不做」**（实测数字与决策链见 BENCHMARK §2.11）。

> 把「做不到」和「做得到但不做」混成一句话，读者就无法判断这是能力缺口还是工程取舍——而这两件事在面试里被追问的方向完全不同。

> **v2.2 又试了一次，换的是判据维度**：不谈 UA，谈**扫什么路径**（`/.git/HEAD`、`/.env`、`/HNAP1`…）。路径判据在真实流量上 0 误报、抓到 8 条真探测，但**这一类 8 条样本全是 `GET /` + 一个 UA 指纹**，路径上什么都没有，所以一条也测不到。**这不是判据不行，是样本只考了最容易伪造的那一维**（详见 BENCHMARK §2.12）。

### 4. 仍然是边界：判据表达力的代价（不是 bug）

- **命名实体**（`&lt;script&gt;`）：不解。`&lt;` 在技术博客、论坛、代码示例里太常见，解它等于把「引用了 HTML 的页面」全判成 XSS。这条已写进测试的反面断言。
- **多重编码**（`%2527%2Bo...` 解两轮才成形）：解码链固定三轮，再多的层次要按层展开，收益小、改动面大。
- **`on<event>=` 但后面不是执行函数**（如 `onbeforehellfreezes=alerw(1)`）：不认。要求执行函数是拿误报换来的收窄，这类垃圾载荷的「攻击性」本身也存疑。
- **IIS best-fit 映射**（`%u00abscript%u00bb` → `«script»`）：只解 `%uXXXX`，不把 `«` 折成 `<`。折叠会改变原文，而正常法语文本里就全是 « »。
- **搜索框里输入 `union select`**：会误报。签名判据无法区分「引用语法」与「注入」，这需要上下文（参数名、是否进 WHERE 子句），不是签名能给的。已写进规则的 falsepositives 与测试。
- **通配 / 括号展开 / 内建变量写出来的命令**（v2.1 新增的边界）：`cat /etc/pa[s]swd`、`cat /[e///////]tc/[p//]asswd`、`$[2+2]`、`${IFS}` 拼命令、`$(whoami$())`。这些**不是「分隔符 + 命令名」形状**，而是 shell 的词法特性：方括号 glob、`//` 当无操作分隔、`$[]` 算术、`${IFS}` 当空格。要认这些就得在判据里实现一遍 shell 展开，而那正是「误报换检出」最不划算的一格——正常文本里 `[s]`、`$[` 也不稀奇。OWASP CRS 的 932130 系列就是这一族（本报告漏检里的主要来源），它用的是同一类语法判据，只是把词法特性也收了进去。
